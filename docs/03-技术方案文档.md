## 0. 文档定位

本文是桌面版的**实现契约**，面向开发与验收。Web 版（Flask + Vue + Docker）是唯一行为基准；桌面版在其上做三件事：

1. **前端冻结复用**：Vue 3 的 9 个页面、3 个公共组件、4 个 Pinia store 原样复制，允许改 8 个适配文件；另有图标迁移例外（见 11.10）。
2. **后端 Rust 全量重写**：不保留 Python 运行时、不启动本地 Flask 服务，27 个接口经 Tauri IPC 复刻。
3. **桌面能力扩展**：原生文件对话框与拖拽、系统托盘、单实例、窗口状态记忆、回收站/快照/审计、内置 MCP 服务。

### 0.1 四条实现约定

| # | 约定 | 说明 |
|---|---|---|
| 1 | **Web 版是唯一行为基准** | Python 代码与真实响应高于本文描述；本文与代码冲突时，以 Python 实际行为 + golden fixture 为准 |
| 2 | **禁止统一化重构** | 27 个接口的外层形状、字段名、数组顺序、错误文案必须逐个复刻，不做「统一信封」「统一错误码」 |
| 3 | **`【实现时确认】` 标记** | 表示 API 名称或枚举值需在编码首周用编译 spike 验证，不得凭记忆写死 |
| 4 | **改动边界** | 前端只允许改第 11 节列出的 8 个文件；其余页面与组件零改动 |

### 0.2 已锁定决策摘要

| 项 | 结论 |
|---|---|
| 外壳 | Tauri v2 |
| 前端 | Vue 3 现有代码，hash 路由，IPC 传输 |
| 后端 | Rust，无 Python 运行时 |
| 接口 | 27 个全量移植；前端实际调用 18 个 |
| 对账 | 逐字段 100% 复刻，含缺陷；容差 1e-6 |
| 数据层 | 纯文件系统，无数据库、无加密存储 |
| MCP | 应用内 Streamable HTTP，默认关闭，14 个工具，完整写权限 + 护栏 |
| 联网 | 完全离线，无 updater / CDN / 遥测 |
| 应用标识 | `com.dtsola.xiaoyaobill.desktop`，显示名「小遥账单桌面版」，初始版本 `0.1.0` |

### 0.3 与 Web 版的同源关系

| 维度 | 约定 |
|---|---|
| 定位 | 桌面版是独立产品，不是 Web 版的安装包 |
| 视觉 | 9 个页面的布局、配色、交互 100% 沿用 Web 版 |
| 统计口径 | 逐字段对齐，包括已知缺陷 D1–D7 |
| 数据 | 不读取、不迁移 Web 版的上传目录 |
| 代码 | 前端复制为冻结基线；后端 100% Rust 重写 |
| 迭代 | Web 版冻结，仅修复安全问题；新功能只进桌面版 |

## 1. 技术选型

### 1.1 桌面与运行时

| 技术 | 版本 | 用途 | 选择理由 |
|---|---|---|---|
| **Tauri** | 2.x | 桌面壳、IPC、打包 | 原生 WebView，不打包浏览器内核，体积小；Rust 后端一等公民 |
| **Rust** | 1.95（MSVC） | 后端与业务逻辑 | 单进程、无 GC、类型安全；解析与聚合性能可控 |
| **Vue** | 3.5.x | 前端 | 现有 Web 版代码直接复用 |
| **Vite** | 5.4.x | 前端构建 | 现有构建链，开发热更新快 |
| **Node.js** | 20 LTS / 24 | 前端构建 | 本机 24.11 可用 |
| **Pinia** | 2.1+ | 状态管理 | 与 Web 版一致 |
| **ECharts** | 5.4+ | 数据可视化 | 与 Web 版一致，图表配置零改动 |

### 1.2 Rust crates

| crate | 用途 | 备注 |
|---|---|---|
| `serde` / `serde_json` | 请求/响应序列化 | `preserve_order` 不启用，对象键顺序不参与对账 |
| `tauri` | 桌面壳、IPC、托盘、窗口 | v2 |
| `tauri-plugin-single-instance` | 单实例 | **必须第一个注册** |
| `tauri-plugin-window-state` | 窗口尺寸/位置记忆 | |
| `tauri-plugin-dialog` | 原生文件对话框 | |
| `tauri-plugin-opener` | 系统浏览器打开外链 | |
| `axum` | MCP 的 HTTP 服务 | 与 Tauri 共用 tokio runtime |
| `tokio` | 异步运行时 | 只通过 `tauri::async_runtime` 使用 |
| `rmcp` | MCP 服务端 | 使用 `StreamableHttpService`，锁定 3.x 精确版本 |
| `csv` | CSV 读取 | `flexible(true)` |
| `calamine` | XLSX 读取 | 替代 openpyxl |
| `encoding_rs` | GBK / UTF-8 解码 | 手动处理 BOM |
| `chrono` | 日期时间 | `NaiveDateTime` / `NaiveDate` |
| `regex` / `fancy-regex` | 退款正则、搜索 | `fancy-regex` 兼容 Python 的 lookaround/backref |
| `unicode-normalization` | NFKD（复刻 `secure_filename`） | |
| `sha2` | 文件指纹 | 快照/审计校验 |
| `ulid` | 回收站/快照 ID | 时间有序 |
| `getrandom` | MCP Token 随机数 | CSPRNG；禁止用 ULID 代替 |
| `subtle` | Token 常量时间比较 | |
| `thiserror` | 错误类型 | |
| `tracing` / `tracing-subscriber` | 本地日志 | 不外发 |
| `schemars` | MCP 工具 JSON Schema | 随 rmcp 版本确认 |

### 1.3 明确不引入的技术

| 技术 | 不引入原因 |
|---|---|
| `polars` / `datafusion` | 数据量小（万级），手写聚合更可控、更易复刻 pandas 语义 |
| `rusqlite` / 任何数据库 | 数据层设计为纯文件系统，`bills/` 是唯一真源 |
| `reqwest` / 任何 HTTP 客户端 | 无出站请求，应用完全离线 |
| `tauri-plugin-updater` | 不做自动更新，避免网络请求与隐私叙事冲突 |
| Electron / Node 后端 | 包体 80–120 MB，自带 Chromium 与 Node，隐私叙事弱，且不满足 Rust 重写要求 |
| Python sidecar | 需打包解释器与依赖（30–50 MB 起），两套运行时、两套日志，隐私解释成本高 |
| PWA / 纯网页 | 不是桌面应用，无法满足原生文件、托盘、单实例、MCP 常驻 |
| Flutter / 原生 UI | 前端无法复用，等于重做产品 |

### 1.4 候选方案对比与否决理由

| 方案 | 包体积 | 后端语言 | 前端复用 | 隐私叙事 | 结论 |
|---|---|---|---|---|---|
| **Tauri v2 + Rust** | ~8–15 MB | Rust | 95%+ | 强（系统 WebView、无 Node、无云） | **采用** |
| Electron + Node | ~80–120 MB | Node/TS | 100% | 弱（自带 Chromium、Node 运行时） | 否决 |
| Tauri + Python sidecar | ~30–50 MB + Python 运行时 | Python | 100% | 中（需打包解释器与依赖） | 否决 |
| PWA / 纯网页 | 0 | 需服务端 | 100% | 中 | 否决 |
| Flutter / 原生 | ~20 MB | Dart/Swift/C# | 0% | 强 | 否决 |

**为什么是 Tauri v2**：

1. 原生 WebView：Windows 用 WebView2，macOS 用 WKWebView，不打包浏览器内核，安装包小。
2. Rust 后端是一等公民：业务逻辑、文件解析、统计聚合都放同一进程，不需要本地 HTTP 服务。
3. 安全模型清晰：CSP、capabilities、IPC 白名单，默认不暴露任何系统能力。
4. 官方插件覆盖需求：dialog、opener、single-instance、window-state 均为官方维护。
5. 社区与文档成熟：v2 已稳定，`rmcp` 官方 Rust SDK 提供 Streamable HTTP 服务端。

### 1.5 版本锁定策略

- `rust-toolchain.toml` 固定 `channel = "1.95"`。
- `rmcp` 锁定 3.x 精确版本；`StreamableHttpService::new` 的参数顺序与类型以该版本为准【实现时确认】。
- Tauri 与插件版本在 `src-tauri/Cargo.toml` 与根 `package.json` 中锁定，升级需单独提交并跑全量对账。
- 产品版本唯一真源为 `src-tauri/tauri.conf.json` 的 `version`。

## 3. 运行时架构与状态

### 3.1 单进程模型

一个进程内同时存在：

1. WebView（Vue 构建产物）
2. Tauri IPC → `api_request` → `bill-api`
3. axum MCP → `bill-mcp` → `bill-services`
4. 文件系统数据层

三者共享同一个 `AppState`，**禁止第二份缓存**。

```
┌──────────────────────────── 单个桌面进程 ────────────────────────────┐
│                                                                      │
│  ┌──────────────── WebView ────────────────┐                         │
│  │  Vue 3 + Vite 构建产物（9 页面）          │                         │
│  │  views / stores / components（0 改动）    │                         │
│  │  src/api/client.js（传输层适配）          │                         │
│  └──────────────────┬─────────────────────┘                         │
│                     │ Tauri IPC (invoke)                             │
│                     ▼                                                │
│  ┌──────────────── Rust Core ─────────────────────────────────────┐  │
│  │  api router (27 routes) → services (统计/洞察/图表)             │  │
│  │                        → parsers (支付宝/微信 CSV/XLSX)          │  │
│  │                        → store (bills/trash/snapshots/audit)     │  │
│  │  AppState = RwLock<内存缓存 + 会话/演示状态>                     │  │
│  └──────────────────▲─────────────────────────────────────────────┘  │
│                     │ 同一套 service 调用                            │
│  ┌──────────────────┴─────────────────────────────────────────────┐  │
│  │  MCP Server (axum + rmcp Streamable HTTP)                       │  │
│  │  127.0.0.1:17650  Bearer Token  默认关闭                         │  │
│  └──────────────────▲─────────────────────────────────────────────┘  │
│                     │ HTTP（仅本机）                                  │
└─────────────────────┼────────────────────────────────────────────────┘
                      │
              ┌───────┴────────┐
              │ 外部 Agent      │  Claude Code / Cursor / 其他 MCP 客户端
              └────────────────┘
```

### 3.2 AppState

```rust
pub struct AppState(pub Arc<AppInner>);

pub struct AppInner {
    pub paths: AppPaths,                 // 数据目录
    pub clock: Arc<dyn Clock>,           // 可注入时钟，测试冻结
    pub settings: RwLock<Settings>,      // std::sync，短临界区
    pub runtime: RwLock<RuntimeState>,   // 演示模式、会话、文件列表、generation
    pub mutation: tokio::sync::Mutex<()>,// 串行化写操作
    pub dataset: DatasetCell,            // 惰性加载 / 就绪 / 失败
    pub mcp: tokio::sync::Mutex<McpHost>,// MCP 生命周期
}

pub struct RuntimeState {
    pub is_demo: bool,
    pub user_id: Option<String>,         // "user_local" / "demo_user"
    pub session_start: String,
    pub files: Arc<Vec<FileEntry>>,
    pub generation: u64,                 // 数据变更 +1
    pub parse_errors: Vec<ParseError>,
}
```

### 3.3 并发规则

| 规则 | 说明 |
|---|---|
| 读请求 | 在 `RwLock` 中 clone `Arc<Dataset>` 后立即释放；分析在 `spawn_blocking` 中执行 |
| 写请求 | 先取 `mutation` 锁；落盘完成后构建新 `Arc<Dataset>`，在写锁内一次性替换 |
| 锁顺序 | `mutation` → `runtime` → `settings` → `mcp`，禁止反向 |
| 禁止 | 跨 `.await` 持有 `std::sync::RwLock`；在 `setup` 中创建第二个 tokio Runtime |
| 异步 | 全部使用 `tauri::async_runtime::spawn`；MCP 的 axum 服务也在其中启动 |
| CPU/磁盘重活 | `spawn_blocking`（解析、全量聚合） |

**不使用全局大 Mutex**：否则 MCP 读工具会阻塞 GUI 分析。

### 3.4 启动与退出流程

```
fn main()                       // 普通 main，不要 #[tokio::main]
  → tauri::Builder::default()
  → 注册 single-instance（第一个）
  → 注册 dialog / opener / window-state
  → .setup(|app| {
       解析平台数据目录并拼 `xiaoyaobill-desktop`，创建目录布局，写 schema_version
       读取 settings.json / session.json / mcp_token（缺失则原子写默认值）
       构建 AppState 并 app.manage()
       初始化托盘
       窗口 visible:false，首帧后 show()，避免白屏
       spawn 预热：扫描 bills/ → 解析 → DatasetCell = Ready
       若 settings.mcp.enabled，spawn 启动 MCP（失败只记录，不阻断）
     })
  → .invoke_handler(generate_handler![api_request, desktop_info, ...])
  → .run(|app, event| 处理 ExitRequested：先停 MCP 再退出)
```

- 启动时若 `session.json.is_demo=true`，加载内嵌示例数据而不是 `bills/`。
- 无任何出站网络请求；不检查更新。
- 首次启动不导入任何旧数据，不扫描用户其他目录。

### 3.5 DatasetCell 状态机

```rust
pub enum DatasetSlot {
    Uninit,
    Loading,
    Ready(Arc<Dataset>),
    Failed(String),
}
```

- `ensure_dataset().await`：Ready 直接返回；Loading 等待 `Notify`；Failed 返回错误。
- 无账单时返回空 Dataset；各 handler 按 Python 行为返回「未找到账单」错误，而不是 panic。
- 导入/删除/清空后重建 Dataset 并 `notify_waiters()`。

## 4. IPC 契约

### 4.1 通用命令

```rust
#[derive(serde::Deserialize)]
pub struct ApiRequest {
    pub method: String,                       // GET | POST | DELETE
    pub path: String,                         // 不含 /api 前缀，如 "/yearly_analysis"
    #[serde(default)]
    pub query: std::collections::BTreeMap<String, String>,
    #[serde(default)]
    pub body: serde_json::Value,              // 仅 /upload 等使用
}

#[tauri::command]
pub async fn api_request(
    state: tauri::State<'_, AppState>,
    req: ApiRequest,
) -> Result<serde_json::Value, String>;
```

### 4.2 返回语义

| 情况 | 返回 |
|---|---|
| 业务成功 | Python 响应体原样（`Value`） |
| 业务失败（`success:false`、404 分类不存在等） | 同样作为 `Value` 返回，不抛错 |
| 传输级错误（panic、锁中毒、无法读盘） | `Err("中文错误信息")` |

前端 `normalize()` 保持旧逻辑：只有 `success === false` 才 `throw Error(error)`；`data` 字段解包；其余去掉 `success` 返回。**不引入 HTTP status 概念**。

### 4.3 路由分发与路径校验

```rust
match (req.method.as_str(), req.path.as_str()) {
    ("GET", "/analysis") => handlers::analysis::get_analysis(&ctx, &req.query),
    ("GET", "/yearly_analysis") => handlers::analysis::yearly_analysis(&ctx, &req.query),
    // ... 其余静态 GET
    ("POST", "/upload") => handlers::files::upload(&ctx, &req.body),
    ("GET", "/files") => handlers::files::list(&ctx),
    ("POST", "/clear_data") => handlers::files::clear(&ctx),
    ("POST", "/demo/enter") => handlers::session::enter(&ctx),
    ("POST", "/demo/exit") => handlers::session::exit(&ctx),
    ("GET", "/session/status") => handlers::session::status(&ctx),
    ("DELETE", p) if p.starts_with("/files/") => handlers::files::delete(&ctx, &p[7..]),
    ("GET", p) if p.starts_with("/category_detail/") => { /* 2 段，解码 */ }
    ("GET", p) if p.starts_with("/category_trend/") => { /* 1 段，解码 */ }
    _ => Ok(json!({"success": false, "error": format!("接口不存在: {}", req.path)})),
}
```

**路径参数**：仍放在 `path` 字符串中，前端 20 个业务方法零改动。Rust 侧解码后必须校验：

- 拒绝空段、`.`、`..`、`/`、`\`、NUL；
- `/files/<filename>` 只允许 basename；
- `canonicalize()` 后父目录必须等于 `<app_data>/bills/`。

### 4.4 查询参数解析

逐接口复刻 Flask 的 `request.args.get(..., type=...)` 语义：

| 类型 | 规则 |
|---|---|
| `int` | `trim()` 后解析；失败视为未传 |
| `float` | 同上 |
| `str` | 原样 |
| 存在性 | 注意 `hour=0` 生效（`is not None`），`min_amount=0` 被忽略（`if min_amount:`），逐接口照抄 |

### 4.5 前端 `client.js` 适配

```js
// frontend/src/api/client.js
import { invoke } from '@tauri-apps/api/core'

const api = {
  // 18 个在用方法与 2 个未用方法保持原样
  getYearlyAnalysis: (params) => get('/yearly_analysis', params),
  // ...
  uploadFile: (input) => post('/upload', normalizeUpload(input)),
  uploadPaths: (paths, provider) => post('/upload', { paths, provider }),
  deleteFile: (filename) => delete_(`/files/${encodeURIComponent(filename)}`),
  // ...
}

async function request(method, path, query, body) {
  try {
    return await invoke('api_request', {
      req: { method, path, query: query ?? {}, body: body ?? null }
    })
  } catch (e) {
    throw new Error(typeof e === 'string' ? e : '请求失败')
  }
}

function normalize(data) {
  if (data && typeof data === 'object' && 'success' in data && !data.success) {
    throw new Error(data.error || '请求失败')
  }
  if (data && typeof data === 'object' && 'data' in data) return data.data
  if (data && typeof data === 'object') {
    const { success, ...rest } = data
    return rest
  }
  return data
}

async function get(endpoint, params) {
  const query = {}
  for (const [k, v] of Object.entries(params ?? {})) {
    if (v !== undefined && v !== null && v !== '') query[k] = String(v)
  }
  return normalize(await request('GET', endpoint, query, null))
}

async function post(endpoint, data) {
  return normalize(await request('POST', endpoint, {}, data ?? null))
}

async function delete_(endpoint) {
  return normalize(await request('DELETE', endpoint, {}, null))
}
```

> `getSessionStatus()` 保留原有特殊处理（字段形状与普通接口不同）。

| `direction` | `String` | 收/支 | 支出 |
| `amount` | `f64` | 交易金额原值（与 DataFrame 一致，通常为正；退款/撤销时为负） | 128.50 |
| `category` | `String` | 交易分类 | 餐饮美食 |

### 6.2 输入格式与编码

| 来源 | 格式 | 编码 / 引擎 | 表头识别 |
|---|---|---|---|
| 支付宝 | CSV | 先 GBK，`UnicodeDecodeError` 回退 UTF-8 | 扫描首个包含 `交易时间` 的行 |
| 微信 | CSV | UTF-8-sig（去 BOM） | 扫描同时包含 `交易时间` 与 `交易类型` 的行 |
| 微信 | XLSX | `calamine` | 扫描每行拼接文本，含 `交易时间` 且（含 `交易类型` 或 `金额`） |

### 6.3 来源探测（复刻 `utils/file_utils.py:22-37`）

```
.xlsx                          → wechat
.csv 前 1024 字节 utf-8-sig    → 含 "微信支付账单" ? wechat : alipay
读取失败                        → alipay
```

### 6.4 支付宝解析（复刻 `parsers/alipay.py`）

1. 解码：**先 UTF-8，失败再 GBK**。Python 是 GBK 优先，但 WHATWG GBK（encoding_rs）会把部分 UTF-8 字节当作合法 GBK 解出乱码，Python 的 gbk codec 则会报错；真实支付宝导出是 GBK，不可能是合法 UTF-8，因此顺序调换不会误判。
2. 找 `header_row`：首个包含 `交易时间` 的行；从该行开始读 CSV。
3. 找 `status_row`：首个包含 `交易状态` 的行；读该行得到列名。
4. **复刻缺陷 D1**：`status_column = 该行的第一列列名`（通常是 `交易时间`），随后判断 `df[status_column].isin(['退款成功','交易关闭'])`。实际恒为 False。
5. 解析 `交易时间`；派生 `月份=YYYY-MM`、`日期=YYYY-MM-DD`。
6. 退款行金额取负（因第 4 步恒 false，实际不触发）。
7. `来源="支付宝"`。
8. 字段补全：缺 `交易对方`→`未知`；缺 `收/支`→`/`；缺 `商品说明` 且有 `商品`→复制，否则空；缺 `交易分类`→`其他`。
9. **不复刻修复 D2**：不增加 `金额（元）→金额` 映射；若文件使用该列名，按 Python 行为报错。
10. **Rust 强类型带来的必要差异**：`交易时间` 或 `金额` 无法解析的行直接跳过（Python 版保留为 NaT/NaN 行，但不进入年份与金额统计）。

### 6.5 微信 CSV（复刻 `parsers/wechat.py:10-75`）

1. UTF-8-sig 解码。
2. 表头必须同时包含 `交易时间` 与 `交易类型`。
3. 列名映射：`交易类型→交易分类`、`商品→商品说明`、`金额(元)→金额`、`当前状态→交易状态`、`支付方式→收/付款方式`。
4. 金额清洗：转字符串 → 去 `¥` → 去 `,` → 转 f64。
5. 退款：`交易状态` 匹配 `退款|关闭|撤销`（忽略大小写）→ `是否退款=true`，金额取负绝对值。
6. 派生 `月份`、`日期`；`来源="微信"`；字段补全同支付宝。

### 6.6 微信 XLSX（复刻 `parsers/wechat.py:78-154`）

1. `calamine` 读取工作簿第一张表，所有行按字符串数组处理。
2. 动态表头扫描（不固定第 17 行）。
3. 必须存在 `交易时间`，否则返回「不是有效的微信账单文件」。
4. `金额(元)` 存在且无 `金额` 时重命名。
5. 其余映射、清洗、退款、派生同 CSV。
6. Excel 日期单元格：`calamine::Data::DateTime` 需按 Excel 序列转换；不要按字符串硬解析。
7. 空行、合并单元格导致的空值按 Python 的 NaN 语义处理（见第 7 节）。

### 6.7 文件名清洗（复刻 werkzeug `secure_filename`）

顺序必须一致：

1. `NFKD` 归一化 → 仅保留 ASCII → 非 ASCII 丢弃；
2. 路径分隔符替换为空格；
3. 按空白切分后用 `_` 连接；
4. 删除 `[^A-Za-z0-9_.-]`；
5. `strip("._")`；
6. 微信时间戳后缀正则：`^(\d{8}-\d{8})_\d+(\.xlsx|\.csv)$` → 去掉 `_数字`；
7. 同名追加 `_1`、`_2`。

**已知后果 D3**（复刻，不修复）：`支付宝账单.csv` → `csv`（无扩展名），列表与解析均不可见。现有 Settings 指南已要求用户重命名为 `alipay_record_2026.csv`，因此保留该行为。

### 6.8 合并与排序

- 扫描 `bills/` 下所有 `.csv` / `.xlsx`，逐文件解析，`concat` 后按 `交易时间` 升序。
- 排序稳定性：同一时间的多行保持文件读取顺序（文件名升序、文件内行序）；用 fixture 钉死。
- 不做去重（复刻 D4：重复导入统计翻倍）。

### 6.9 演示数据

- 内嵌 `sample_data.csv`（7,396 条，`include_str!` 编译进二进制）。
- **不排序**（复刻 `data_loader.py` 的演示分支）。
- 演示模式下所有写操作被拒绝。

实现位置：`bill-services/src/pycompat.rs` 与 `bill-api/src/query.rs`。每个函数必须有对照单测。

### 7.1 18 项兼容规则

| # | Python/pandas 行为 | Rust 实现要求 | 测试值 |
|---|---|---|---|
| 1 | `round(x, n)` 银行家舍入，且基于二进制精确值 | 先尝试 `format!("{:.*}", n, x).parse()`；与 golden 不符时移植 CPython `round` 算法 | `2.675→2.67`、`1.005→1.0`、`0.125→0.12` |
| 2 | `np.round` 缩放后 `rint`（half-even） | `(x * 10f64.powi(n)).round_ties_even() / 10f64.powi(n)` | `2.675→2.68`、`10.235→10.24` |
| 3 | `np.quantile` / `np.percentile` 默认线性插值 | 排序后 `h=(n-1)q`，`lo=floor(h)`，线性插值 | `[10,20,30,40]`，q20/40/60/80 → `16/22/28/34` |
| 4 | `std()` 默认 `ddof=1` | `sqrt(Σ(x-mean)²/(n-1))`；n<2 → NaN | `[10,20,30]→10`；单值→NaN |

| 7 | `pd.cut(..., right=False)` | 左闭右开 `[a,b)` | `50→[50,100)`，`100→NaN` |
| 8 | `to_period('M'/'Q')` | 月/季度归属；季度 = `(month-1)/3+1` | 跨年、12 月 |

### 7.2 金额精度

- 继续使用 `f64`（与 Python 一致），**不使用 Decimal**。
- 所有输出在序列化前按接口原有精度 `round`。
- 计数类字段必须是整数；金额类允许 1e-6 相对误差。

### 7.3 禁止 NaN / Infinity

- 任何接口响应中不得出现 `NaN`、`Infinity`。
- Rust 序列化前做统一检查；golden 生成使用 `json.dumps(..., allow_nan=False)`。
- 空值按接口语义显式转换为 `0`、`""`、`null` 或省略字段，逐接口对齐。

### 8.7 审计日志

每行一个 JSON：

```json
{
  "ts": "2026-11-11T12:00:00.123+08:00",
  "event": "clear_data",
  "phase": "intent | result | recovered",
  "actor": {"kind": "ui | mcp", "tool": "clear_data", "session_id": "..."},
  "request_id": "01J...",
  "before": {"file_count": 3, "total_bytes": 400000, "generation": 41},
  "after": {"file_count": 0, "total_bytes": 0, "generation": 42},
  "target": {"files": ["a.csv", "b.xlsx"]},
  "trash_id": null,
  "snapshot_id": "01J...",
  "result": "ok | err",
  "error": null,
  "duration_ms": 37,
  "app_version": "0.1.0",
  "schema_version": 1
}
```

- 破坏性操作写 `intent` + `result` 两行；启动发现只有 intent 的补 `recovered`。
- 不记录 Token；默认只记录文件名，不记录完整路径。
- 审计写失败时，破坏性操作 **fail-closed**（拒绝执行）。
- **永不自动清理**；设置页显示大小并可手动清空。

### 8.8 启动 reconcile

- 以 `bills/` 为真源。
- 清理 `tmp/` 残片。
- 对只有 `intent` 的审计补 `recovered`。
- 孤儿 trash/snapshot 目录保留并标记，不自动删除。

## 9. MCP 服务

### 9.1 传输与鉴权

| 项 | 实现 |
|---|---|
| 协议 | MCP Streamable HTTP（JSON-RPC + SSE 响应） |
| 服务 | `rmcp::transport::streamable_http_server::StreamableHttpService` + `LocalSessionManager` |
| HTTP | `axum::Router::new().nest_service("/mcp", service)` |
| 监听 | `127.0.0.1:17650`，固定端口；不监听 `0.0.0.0` |
| 鉴权 | `Authorization: Bearer <token>`，`subtle` 常量时间比较 |
| Origin | 缺失（原生客户端）或 `http://127.0.0.1:*` / `http://localhost:*` 才放行 |
| Body | 限制 1MB |
| TLS | 无（仅回环） |
| CORS | 不启用通配 |

启动代码骨架：

```rust
pub async fn start(state: AppState, token: Arc<str>) -> Result<McpHandle, McpError> {
    let listener = tokio::net::TcpListener::bind(("127.0.0.1", 17650)).await?;
    let service = StreamableHttpService::new(
        { let s = state.clone(); move || Ok(BillMcp::new(s.clone())) },
        Arc::new(LocalSessionManager::default()),
        StreamableHttpServerConfig::default(),
    );
    let app = axum::Router::new()
        .nest_service("/mcp", service)
        .layer(axum::middleware::from_fn_with_state(Auth { token }, bearer_check))
        .layer(axum::extract::DefaultBodyLimit::max(1024 * 1024));
    let (tx, rx) = tokio::sync::oneshot::channel::<()>();
    tauri::async_runtime::spawn(async move {
        axum::serve(listener, app)
            .with_graceful_shutdown(async { let _ = rx.await; })
            .await
    });
    Ok(McpHandle { shutdown: tx })
}
```

> `StreamableHttpService::new` 的参数顺序与类型以锁定的 rmcp 3.x 版本为准【实现时确认】。

### 9.2 生命周期

| 场景 | 行为 |
|---|---|
| 应用启动且 `mcp.enabled=true` | 异步启动；失败写 `mcp.last_error` 并通知前端，不阻断启动 |
| 设置页开启 | 校验端口 → 启动 → 更新状态 |
| 设置页关闭 | graceful shutdown（3s 超时）→ abort |
| 重新生成 Token | 停止 → 写新 Token → 重启 |
| 端口占用 | 保持关闭，返回明确错误 |
| 应用退出 | 先停 MCP 再退出 |
| 演示模式 | 读工具返回示例数据；写工具返回 `{"success":false,"error":"演示模式下禁止写入"}` |

### 9.4 写工具语义

```
参数校验（confirm、路径、扩展名、大小）
→ 演示模式检查
→ 取 mutation 锁
→ （clear_data）创建快照并校验；失败则拒绝
→ 执行（导入/软删除/恢复）
→ 重建 Dataset
→ 写 audit intent + result
→ 返回结构化结果
```

- `import_bill`：仅接受绝对路径；必须是常规文件；扩展名 `csv/xlsx`；≤16MB；复制入 `bills/`；不覆盖；逐文件返回结果。
- `delete_bill`：只接受 basename；移动到 `trash/<ulid>/`；返回 `trash_id`。
- `restore_bill`：按 `trash_id` 恢复全部文件；重名加序号。
- `clear_data`：`confirm` 必须为 `true`；先快照，再清空；返回 `snapshot_id`。

### 9.5 MCP 与 GUI 一致性

- 同一 `AppState`、同一数据、同一演示状态。
- MCP 写操作完成后，GUI 下一次请求自然读到新数据；当前已打开的页面不主动刷新（已知限制，见 17.3）。
- MCP 的返回字段与对应 REST 接口一致，避免 Agent 与界面看到不同数字。

## 13. 安全与隐私

| 面 | 措施 |
|---|---|
| 网络 | 无出站请求；不集成 updater；不加载 CDN；外链交系统浏览器 |

| 审计 | 写操作 intent/result；不含 Token |

### 14.2 Windows

- 本机 `cargo tauri build`，产物为 NSIS 每用户安装包。
- 不做代码签名；SmartScreen 可能提示。
- 安装/卸载不删除用户数据目录，安装器展示数据路径。

### 14.3 macOS

- 无本地 Mac，使用 GitHub Actions。
- 分架构构建，不做 universal：
  - `macos-13` → `x86_64-apple-darwin`
  - `macos-14` → `aarch64-apple-darwin`
- 产物：两个 `.dmg` + `.app`。
- 未签名、未公证；首次打开需「系统设置 → 隐私与安全性 → 仍要打开」，macOS 15 可能需要该路径或 `xattr -dr com.apple.quarantine`。

```yaml
name: macos-build
on:
  workflow_dispatch:
  push:
    tags: ["v*"]
jobs:
  build:
    strategy:
      matrix:
        include:
          - runner: macos-13
            target: x86_64-apple-darwin
          - runner: macos-14
            target: aarch64-apple-darwin
    runs-on: ${{ matrix.runner }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - uses: dtolnay/rust-toolchain@stable
        with: { targets: "${{ matrix.target }}" }
      - uses: Swatinem/rust-cache@v2
      - run: npm ci
      - run: npm --prefix frontend ci
      - uses: tauri-apps/tauri-action@v0
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          args: --target ${{ matrix.target }}
      - uses: actions/upload-artifact@v4
        with:
          name: macos-${{ matrix.target }}
          path: src-tauri/target/${{ matrix.target }}/release/bundle/dmg/*.dmg
```

- golden 对账 100%，`git diff --exit-code fixtures/expected` 无输出。

- 断网启动无外部请求。
- Windows 干净环境安装冒烟；macOS 两个架构产物可打开。

## 15. 性能指标

### 15.1 目标值

| 指标 | 目标 | 说明 |
|---|---|---|
| 冷启动 | ≤2s（无账单）/ ≤3s（1 万条） | 到主界面可交互 |
| 接口响应 | P95 ≤50ms（1 万条，IPC 往返） | 分析类接口 |
| 内存常驻 | ≤200MB | 含 WebView |
| Windows 安装包 | ≤20MB | NSIS |
| macOS 单架构安装包 | ≤25MB | dmg |
| 图表渲染 | ≤500ms | 100 个数据点 |
| 搜索响应 | ≤500ms | 1 万条内关键词搜索 |

### 15.2 性能设计

- 启动加载一次账单到内存，后续分析不再重复解析（修复 Web 版每次请求重解析的问题）。
- 读请求 clone `Arc<Dataset>` 后在 `spawn_blocking` 中计算。
- 大数据量按 `(generation, params)` 缓存分析结果；数据变更时 `generation + 1` 自然失效。
- 前端图表沿用 Web 版配置，不做额外优化。

### 15.3 容量假设

- 单用户、单机；账单总量 1–10 万条。
- 单文件 ≤16MB；单次最多选择 20 个文件（MCP 导入上限）。
- 数据目录长期增长由回收站/快照/审计贡献，设置页提供占用显示与手动清理。

## 17. 已知偏差与技术债

### 17.1 有意保留的 Web 版缺陷（100% 复刻）

| # | 缺陷 | 影响 | 位置 |
|---|---|---|---|
| D1 | 支付宝退款状态列取「第一列列名」 | 退款永不标记，退款行按支出计入 | `parsers/alipay.py:49-64` |
| D2 | 支付宝缺少 `金额（元）` 映射 | 使用该列名的文件解析报错 | `parsers/alipay.py` |
| D3 | 中文文件名被 `secure_filename` 洗成 `csv`/`xlsx` | 文件不可见、不参与解析 | `utils/file_utils.py:40-81` |
| D4 | 重复导入不去重 | 统计翻倍 | `utils/file_utils.py` |
| D5 | `/api/summary` 的上月取「倒数第二个月」 | 与自然月不符 | `analysis.py:1334` |
| D6 | `/api/yearly_data` 月份不补齐 | 仅含数据中出现的月份 | `analysis.py:266` |
| D7 | 部分接口不排除退款行 | 统计口径不一致 | 多个 handler |

> 以上缺陷**不在本版本修复**。修复必须作为独立版本的行为变更，并同步更新 golden 与用户说明。

### 17.2 桌面端有意差异

| 项 | Web 版 | 桌面版 | 理由 |
|---|---|---|---|
| 删除文件 | 物理删除 | 软删除到回收站 | 可恢复 |
| 清空数据 | 直接删除目录 | 先快照再清空 | 可恢复 |
| 会话 | Flask Cookie/文件会话 | 本地 `session.json` | 无浏览器 |
| 关闭页面 | 关闭浏览器标签 | 隐藏到托盘 | MCP 常驻 |
| 上传 | multipart 到 Flask | 原生路径 + Rust 读盘 | 桌面能力 |
| 审计 | 无 | 写操作记录 | MCP 可写 |

### 17.3 已知限制

- MCP 写操作后，已打开的页面不会自动刷新；切换页面或重新进入时更新。
- 回收站/快照/审计日志永不自动清理，长期使用会占盘；设置页提供手动清理与占用显示。
- macOS 未签名，安装体验有摩擦。
- Windows 10 若缺失 WebView2，应用无法启动。
- 不提供导出、自动更新、深色模式。

### 17.4 缺陷修复原则

1. 修复必须作为独立版本的行为变更，不在接口移植中顺带修改。
2. 修复前先更新 golden 与用户说明，明确统计口径变化。
3. 修复后必须跑全量对账，确认无其他接口回归。
