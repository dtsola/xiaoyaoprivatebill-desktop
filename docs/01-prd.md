## 2. 定位与边界

### 2.1 产品定位

**为注重隐私的个人用户，提供一款完全离线、可被 AI Agent 调用的桌面账单分析工具。**

- 产品形态：Windows / macOS 桌面应用
- 数据处理：全部在本机完成，不发起任何出站网络请求
- 核心能力：支付宝 / 微信账单导入、多维度分析、本地 MCP 服务
- 与 Web 版关系：独立产品，视觉与统计口径对齐，数据不互通

### 2.2 与 Web 版的五条约定

| 维度 | 约定 |
|---|---|
| 定位 | 桌面版是独立新产品，不是 Web 版的安装包 |
| 视觉 | 9 个页面的布局、配色、交互 100% 沿用 Web 版 |
| 统计口径 | 逐字段对齐，**包括已知缺陷 D1–D7** |
| 数据 | 不读取、不迁移 Web 版的上传目录 |
| 代码 | 前端复制为冻结基线（只允许改 8 个文件）；后端 100% Rust 重写 |

Web 版在本期冻结，仅修复安全问题；新功能只进桌面版。

### 2.3 非目标（本期明确不做）

| 非目标 | 原因 |
|---|---|
| 账号体系、云同步、多设备 | 与「数据不出本机」冲突 |
| 自动更新、遥测、崩溃上报 | 任何启动期网络请求都会破坏隐私承诺 |
| CSV / PDF / 图片导出 | 现有 Web 版无此功能，本期保持对齐 |
| 自动记账、银行直连 | 超出账单分析范围 |
| 多用户 / 多账本 | 现有数据模型是单用户 |
| 旧版 Web 数据自动迁移 | 用户重新导入原始账单即可 |
| 深色模式 | 现有 CSS 无暗色主题，本期不新增设计 |
| 代码签名与公证 | 首期不做，文档标注安装摩擦 |

## 3. 用户故事

### 3.1 US-1：离线分析

> 作为一位注重隐私的用户，我想要把支付宝和微信的年度账单导入桌面应用，以便在不联网的情况下看清钱花在哪。

**验收**：导入 1 个支付宝 CSV + 1 个微信 XLSX 后，首页、年度、月度、分类、时间、洞察、明细 7 个页面均有数据；断网状态下功能不受影响。

### 3.2 US-2：先体验再导入

> 作为第一次打开应用的用户，我想要先看演示数据，以便确认这个工具值得我导入真实账单。

**验收**：点击「体验演示数据」进入演示模式，9 个页面展示内置 7,396 条示例数据；演示模式下无法导入、删除、清空。

### 3.3 US-3：Agent 自然语言查账

> 作为使用 Claude Code / Cursor 的用户，我想要让 Agent 直接查询我的账单，以便用对话完成「上个月餐饮花了多少」「哪几天消费最高」这类分析。

**验收**：在「AI Agent 接入」页开启 MCP 并复制配置到 Agent，Agent 能列出 14 个工具，调用 `get_monthly_analysis` 返回与界面一致的数字。

### 3.4 US-4：Agent 自动化导入

> 作为把账单下载到固定目录的用户，我想要让 Agent 自动导入新账单，以便不用手动点选文件。

**验收**：Agent 调用 `import_bill(path)` 成功入库；重复路径再次导入按 Web 版规则生成新文件名并重复计入（已知行为，见 6.5）。

### 3.5 US-5：可恢复的删除

> 作为担心 Agent 误操作的用户，我想要删除可恢复、清空有快照、操作有记录，以便出了问题能查、能还原。

**验收**：`delete_bill` 后文件进入回收站并可 `restore_bill`；`clear_data` 生成快照；设置页可查看审计日志与回收站。

### 3.6 故事—功能—页面映射

| 故事 | 主要功能 | 页面 |
|---|---|---|
| US-1 | F1、F3–F8 | 首页、年度、月度、分类、时间、洞察、交易 |
| US-2 | F9 | 首页、全部页面 |
| US-3 | F12 | 设置（桌面分组） |
| US-4 | F12 | 设置（桌面分组） |
| US-5 | F2、F11、F12 | 设置（桌面分组） |

## 5. 桌面端功能需求

### 5.1 原生文件导入

| 规则 | 值 |
|---|---|
| 入口 | 设置页两个上传区（支付宝 / 微信）；全窗口拖拽 |
| 支付宝 | 仅 `.csv`，编码 GBK（失败回退 UTF-8） |
| 微信 | `.xlsx` 或 `.csv`，UTF-8-sig |
| 大小限制 | 单文件 ≤16MB（16,777,216 字节） |
| 来源识别 | 由后端按文件内容判定，不信任扩展名 |
| 多文件 | 支持一次选择多个，逐个导入并汇总结果 |
| 重复文件 | 按 Web 版规则：同名不同内容追加 `_1`、`_2`；允许重复计入 |
| 失败处理 | 单个文件失败不阻断其余文件；逐条提示文件名与原因 |

### 5.2 系统托盘

| 行为 | 规则 |
|---|---|
| 图标常驻 | 默认开启；托盘图标使用应用 Logo |
| 关闭窗口 | 隐藏到托盘，进程继续运行 |
| 首次关闭 | 弹一次提示：「已最小化到托盘，MCP 服务继续运行。可在设置中改为关闭即退出。」 |
| 托盘菜单 | 显示主窗口 / MCP：开·关 / 打开数据目录 / 退出 |
| 设置项 | 「关闭窗口时：最小化到托盘（默认） / 直接退出」 |
| macOS | 同时保留 Dock 图标；菜单栏使用系统模板图标 |

### 5.3 单实例与窗口

| 行为 | 规则 |
|---|---|
| 单实例 | 重复启动时聚焦已有窗口，不创建第二个进程 |
| 窗口默认尺寸 | 1280×840 |
| 最小尺寸 | 1024×700（避免触发 768px 移动端折叠断点） |
| 状态记忆 | 记住尺寸、位置、最大化状态；屏幕变化时回到主屏可见区域 |
| 标题栏 | 隐藏系统原生标题：Windows 自绘 34px 标题栏（整条可拖拽 + 最小化/最大化/关闭）；macOS 用 `titleBarStyle: Overlay` 保留原生红绿灯，只隐藏标题文字 |

### 5.4 设置页「桌面」分组

新增于设置页现有内容之后，不重排原有区块。包含：

1. **数据目录**：显示绝对路径 + 「打开文件夹」按钮。
2. **回收站**：条目数、占用空间、恢复/彻底删除、「打开回收站目录」。
3. **快照**：列表（时间、文件数、大小）、「恢复快照」「删除快照」。
4. **审计日志**：最近 200 条，字段为时间 / 来源（GUI·MCP）/ 工具 / 结果；「打开完整日志」。
5. **清理**：「立即清理回收站」「立即清理审计日志」（永不自动清理）。

> MCP 服务不在设置页内，改为侧边栏独立菜单「**AI Agent 接入**」（`/#/agent`，桌面专属页面）。原有开关、状态、端点、Token 与说明文案整体迁移，规格不变。

### 5.5 关闭与退出

| 操作 | 结果 |
|---|---|
| 点窗口关闭按钮 | 按设置隐藏到托盘或直接退出 |
| 托盘「退出」 | 停止 MCP 服务、刷新设置文件、退出进程 |
| macOS Cmd+Q | 退出进程 |
| 系统关机/注销 | 正常退出，不残留锁文件 |

### 5.6 空状态与错误文案

| 场景 | 文案要求 |
|---|---|
| 无账单 | 引导上传或进入演示模式 |
| 不支持的文件类型 | 明确指出允许 `csv/xlsx` |
| 文件超过 16MB | 显示文件大小与上限 |
| 解析失败 | 显示文件名 + 原因，不阻断其他文件 |
| 演示模式写入 | 「演示模式下禁止写入」 |
| MCP 端口占用 | 明确提示端口被占用，服务未启动 |
| 无 Token / 错 Token | HTTP 401（MCP 客户端可见） |

## 6. MCP 功能需求

### 6.1 基本约定

| 项 | 值 |
|---|---|
| 传输 | MCP Streamable HTTP（JSON-RPC over HTTP，支持 SSE 响应） |
| 地址 | `http://127.0.0.1:17650/mcp`，仅绑定回环地址 |
| 鉴权 | `Authorization: Bearer <token>`；Token 32 字节随机数，持久化保存，可轮换 |
| 默认状态 | **关闭** |
| 生命周期 | 随应用启动/停止；应用退出即不可用 |
| 演示模式 | 全局共享；演示模式下读工具返回示例数据，写工具一律拒绝 |
| 并发 | 与 GUI 共享同一份内存状态，读写加锁 |

### 6.2 客户端配置

「AI Agent 接入」页「复制 MCP 配置」生成：

```json
{
  "mcpServers": {
    "xiaoyao-bill": {
      "type": "http",
      "url": "http://127.0.0.1:17650/mcp",
      "headers": {
        "Authorization": "Bearer <TOKEN>"
      }
    }
  }
}
```

Claude Code 也可使用：

```bash
claude mcp add --transport http xiaoyao-bill http://127.0.0.1:17650/mcp \
  --header "Authorization: Bearer <TOKEN>"
```

### 6.3 工具清单（14 个）

| # | 工具 | 类型 | 作用 |
|---|---|---|---|
| 1 | `list_bills` | 读 | 已导入账单列表（名称、大小、来源、导入时间） |
| 2 | `get_overview` | 读 | 可用年份/月份、记录数、当前是否演示模式 |
| 3 | `get_summary` | 读 | 总收入/支出/结余/月均 |
| 4 | `get_yearly_analysis` | 读 | 指定年份的年度分析 |
| 5 | `get_monthly_analysis` | 读 | 指定年月的月度分析 |
| 6 | `get_category_analysis` | 读 | 分类列表或指定分类的趋势/明细 |
| 7 | `search_transactions` | 读 | 多条件筛选 + 分页的交易明细 |
| 8 | `get_time_analysis` | 读 | 小时分布、工作日/周末 |
| 9 | `get_insights` | 读 | 消费洞察全量数据 |
| 10 | `get_audit_log` | 读 | 最近的 MCP / GUI 写操作记录 |
| 11 | `import_bill` | 写 | 按本地绝对路径导入账单 |
| 12 | `delete_bill` | 写 | 软删除到回收站，返回 `trash_id` |
| 13 | `restore_bill` | 写 | 按 `trash_id` 恢复 |
| 14 | `clear_data` | 写 | 生成快照后清空全部账单，返回 `snapshot_id` |

完整入参/返回见 [03-技术方案文档.md](./03-技术方案文档.md) 第 9.3 节。

### 6.4 写操作护栏

| 操作 | 护栏 |
|---|---|
| `import_bill` | 仅绝对路径；扩展名白名单；≤16MB；复制入 `bills/`；不覆盖已有文件 |
| `delete_bill` | 不物理删除，移动到 `trash/`；返回 `trash_id` |
| `restore_bill` | 仅能恢复回收站中的条目；目标名冲突时追加序号 |
| `clear_data` | 先写 `snapshots/<id>/`，再清空 `bills/`；返回 `snapshot_id`；`confirm` 必须为 `true` |
| 所有写操作 | 追加 `audit.jsonl`；演示模式下拒绝执行；错误返回中文 `error` |
| 留存 | 回收站、快照、审计日志**永不自动清理**，仅用户手动清理 |

### 6.5 明确保留的既有行为

| 行为 | 说明 |
|---|---|
| 重复导入 | 不按内容去重；同名文件追加序号；重复交易会重复计入统计（D4） |
| 支付宝退款判定 | 保留 Web 版缺陷：退款行不会被标记为退款（D1） |
| 单用户 | 无账号概念；MCP 与 GUI 看到同一份数据 |

### 6.6 隐私文案

> 开启 MCP 后，本机程序可读取全部账单；数据是否离开本机取决于调用方（Agent）。应用本身不发起网络请求。

## 7. 核心流程

### 7.1 首次启动与导入

```
启动
  → 检查数据目录（不存在则创建）
  → 扫描 bills/ 并解析（无文件则进入空状态）
  → 显示首页
  → 用户点击「导入账单」（或拖拽文件）
  → 原生文件对话框（多选，按来源过滤扩展名）
  → 逐个校验：扩展名 / 大小 / 是否演示模式
  → Rust 读取文件 → 识别来源 → 解析 → 复制入 bills/
  → 刷新内存缓存
  → 提示成功数量与失败原因
```

### 7.2 开启 MCP 并调用

```
设置 → 桌面 → MCP 开关
  → 生成/读取 Token → 绑定 127.0.0.1:17650
  → 显示状态「运行中」
  → 用户复制配置到 Agent
  → Agent 发送 initialize（带 Bearer）
  → 401 则拒绝；200 则返回工具列表
  → Agent 调用工具 → 读取 AppState → 返回 JSON
  → 写工具：执行护栏 → 追加审计 → 返回结果
```

### 7.3 清空与恢复

```
用户/Agent 调用 clear_data
  → 创建 snapshots/<id>/
  → 复制 bills/ 全部文件
  → 清空 bills/
  → 刷新缓存
  → 写审计
  → 返回 snapshot_id
设置页 → 快照 → 恢复
  → 校验 snapshot 存在
  → 将当前 bills/ 先移入 trash/
  → 从快照恢复文件
  → 刷新缓存
```

### 7.4 删除与恢复

```
用户点击删除 / Agent 调用 delete_bill
  → 写 trash manifest（intent）
  → 移动到 trash/<ulid>/files/
  → 重建数据集
  → 写审计（result）
  → 返回 trash_id
设置页 → 回收站 → 恢复
  → 目标重名加序号
  → 文件回到 bills/
  → 重建数据集
```

### 7.5 异常流程

| 异常 | 处理 |
|---|---|
| 文件格式不支持 | 跳过该文件，提示允许的扩展名 |
| 文件超过 16MB | 跳过该文件，提示大小上限 |
| 解析失败 | 跳过该文件，显示文件名与原因 |
| 磁盘写入失败 | 回滚本批已导入文件，提示错误 |
| MCP 端口占用 | 保持 MCP 关闭，GUI 不受影响 |
| 演示模式写操作 | 返回 `{"success":false,"error":"演示模式下禁止写入"}` |

## 9. 非功能需求

### 9.1 性能

| 类别 | 指标 |
|---|---|
| 冷启动 | ≤2s（无账单）；≤3s（1 万条交易） |
| 接口响应 | 1 万条数据下 P95 ≤50ms（IPC 往返） |
| 内存占用 | 常驻 ≤200MB（1 万条数据） |
| 图表渲染 | ≤500ms（100 个数据点） |
| 搜索响应 | ≤500ms（1 万条内） |

### 9.2 体积与平台

| 项 | 指标 |
|---|---|
| Windows 安装包 | ≤20MB |
| macOS 单架构安装包 | ≤25MB |
| 系统 | Windows 10/11 x64；macOS 11+ |
| WebView2 | Windows 10 需已安装；Win11 自带 |

### 9.3 离线与安全

- 断网下全部功能可用；除用户主动点击外链外无任何出站请求。
- CSP `default-src 'self'`；MCP 仅回环；Token 常量时间比较；文件权限 0600/0700。
- 无 CDN、无遥测、无崩溃上报、无自动更新。

### 9.4 数据位置与卸载

| 平台 | 数据目录 |
|---|---|
| Windows | `%APPDATA%\xiaoyaobill-desktop` |
| macOS | `~/Library/Application Support/xiaoyaobill-desktop` |

卸载不自动删除用户数据；安装器提示数据目录位置。

### 9.5 可观测性与可访问性

- 本地日志文件，不上报；MCP 与 GUI 写操作统一审计。
- 可访问性沿用 Web 版现状，本期不新增。

### 9.6 平台差异

| 项 | Windows | macOS |
|---|---|---|
| 窗口关闭 | 隐藏到托盘 | 隐藏到托盘；保留 Dock |
| 退出 | 托盘「退出」 | 托盘「退出」/ Cmd+Q |
| 安装包 | NSIS 每用户 | dmg（x86_64 / aarch64） |
| 签名 | 不做 | 不做；右键打开 |
| WebView | WebView2 | WKWebView |
