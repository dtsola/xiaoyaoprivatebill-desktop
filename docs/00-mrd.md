## 1. 核心问题

### 1.1 一句话问题

**注重隐私的个人用户想从支付宝、微信账单中获得财务洞察，但现有工具要么要求上传数据，要么无法被 AI Agent 安全调用。**

### 1.2 为什么需要桌面版

Web 版（Flask + Vue + Docker）已经验证了「账单解析 + 多维分析」的需求，但存在三个结构性限制：

| # | Web 版的限制 | 桌面版的解决方式 |
|---|---|---|
| 1 | **浏览器沙箱**：网页无法直接读取本地账单，只能 multipart 上传到本地服务 | 原生文件对话框与全窗口拖拽，前端只传路径，Rust 直接读盘 |
| 2 | **启动门槛**：普通用户需要安装 Python/Docker、启动 Flask、打开浏览器 | 双击安装包即用，单进程、无本地 Web 服务 |
| 3 | **无法常驻与系统集成**：没有托盘、单实例、窗口记忆，不能作为「本地数据服务」被 Agent 长期调用 | 系统托盘常驻 + 单实例 + 内置 MCP，Agent 可随时查询与分析 |

### 1.3 本期三个假设

| # | 假设 | 验证方式 |
|---|---|---|
| H1 | 隐私敏感用户愿意安装桌面应用，而不仅是使用网页 | 首发 30 天下载量与安装成功率 |
| H2 | 内置演示数据能降低首次使用门槛 | 演示模式进入率、演示后导入转化率 |
| H3 | 本地 MCP 能让 AI Agent 成为新的查询入口 | MCP 开启率、Agent 工具调用次数、反馈 |

## 2. 目标用户

### 2.1 三类画像

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| **隐私敏感的个人用户** | 使用支付宝/微信日常消费；不愿把账单上传到任何服务器 | 完全离线地看清年度/月度消费结构 |
| **演示体验新用户** | 第一次接触账单分析工具；对导入真实数据有顾虑 | 先用示例数据体验，再决定是否导入 |
| **Agent 用户** | 使用 Claude Code / Cursor 等 MCP 客户端 | 用自然语言查账，让 Agent 完成重复分析 |

### 2.2 痛点场景

1. **账单分散**：消费记录分散在支付宝、微信，难以统一查看。
2. **手动记账累**：传统记账需要逐笔输入，难以坚持。
3. **隐私担忧**：多数记账工具要求上传数据，担心泄露。
4. **缺乏分析**：只有流水记录，没有深入的消费分析与建议。
5. **不知钱去哪了**：月度结余时才发现超支，缺乏实时感知。
6. **Agent 接入无门**：想把 AI Agent 接入个人财务数据，但现有工具没有安全、本地的接口。

### 2.3 当前替代方案与缺口

| 方案 | 优点 | 缺点 | 桌面版机会 |
|---|---|---|---|
| 纯手动记账 | 灵活、隐私可控 | 耗时、难坚持、易遗忘 | 自动解析替代手工 |
| 平台自带账本 | 数据自动同步 | 平台割裂、分析浅、部分收费 | 跨平台整合 + 深度分析 |
| 第三方记账 App | 功能丰富 | 需上传数据、广告多、隐私风险 | 完全离线 |
| Excel / GSheet | 灵活、隐私可控 | 需手动整理、分析门槛高 | 自动解析 + 可视化 |
| 桌面记账软件 | 本地存储 | 多为手动记账、无 Agent 接口 | 自动解析 + 本地 MCP |

### 2.4 非目标用户

- 需要账号体系、云同步、多设备漫游的用户。
- 需要多人协作、多账本的用户。
- 需要银行直连、自动记账的用户。
- 需要移动端 App 的用户。

## 3. 解决方案

### 3.1 产品定位

**为注重隐私的个人用户，提供一款完全离线、可被 AI Agent 调用的桌面账单分析工具。**

- 产品形态：Windows / macOS 桌面应用
- 数据处理：全部在本机完成，不发起任何出站网络请求
- 核心能力：支付宝 / 微信账单导入、多维度分析、本地 MCP 服务
- 与 Web 版关系：独立产品，视觉与统计口径对齐，数据不互通

### 3.2 三支柱

| 支柱 | 内容 | 用户价值 |
|---|---|---|
| **完全离线** | 无出站请求、无 CDN、无遥测、无自动更新；字体图标本地化 | 数据不出本机，隐私可验证 |
| **桌面原生** | 原生文件对话框与拖拽、系统托盘、单实例、窗口状态记忆、本地持久化 | 像本地软件一样好用，不依赖浏览器与服务器 |
| **内置 MCP** | 14 个工具；默认关闭；仅 `127.0.0.1:17650`；Bearer Token；写操作有护栏与审计 | 让 Claude Code / Cursor 等 Agent 安全地查账 |

### 3.3 与 Web 版的关系

| 维度 | 约定 |
|---|---|
| 定位 | 桌面版是独立新产品，不是 Web 版的安装包 |
| 视觉 | 9 个页面的布局、配色、交互 100% 沿用 Web 版 |
| 统计口径 | 逐字段对齐，包括已知缺陷 D1–D7 |
| 数据 | 不读取、不迁移 Web 版的上传目录 |
| 代码 | 前端复制为冻结基线（只允许改 7 个文件）；后端 100% Rust 重写 |
| 迭代 | Web 版冻结，仅修复安全问题；新功能只进桌面版 |

### 3.4 MVP 范围摘要

P0 功能 F1–F13：账单导入、文件管理、年度/月度/分类/时间/洞察分析、交易明细、演示模式、桌面壳、设置页桌面分组、MCP 服务、离线与安全。P1 补齐 9 个兼容接口、审计筛选、回收站批量恢复。P2 的导出、自动更新、签名、深色模式、旧数据迁移不进本期。

完整清单见 [01-prd.md](./01-prd.md) 第 4 节。

## 4. 竞品与差异化

### 4.1 竞品矩阵

| 竞品 | 优势 | 劣势 | 桌面版差异化机会 |
|---|---|---|---|
| 记账城市 | 界面美观、社区活跃 | 需上传数据、广告多 | 完全离线 |
| 钱迹 | 极简设计 | 需上传数据、高级功能收费 | 免费开源、无账号 |
| 支付宝/微信自带账本 | 数据自动同步 | 平台割裂、分析浅 | 跨平台整合 + 深度洞察 |
| Excel / GSheet | 完全灵活、隐私可控 | 手动整理、门槛高 | 自动解析 + 可视化 |
| 通用 AI 记账工具 | 可对话 | 通常依赖云端模型与上传数据 | 本地 MCP + Agent 自带模型 |

### 4.2 真正的差异化

1. **完全离线**：数据不离开本机，且可以断网验证。
2. **可被 Agent 调用**：内置 MCP，Claude Code / Cursor 等可直接查账；这是 Web 版与多数竞品没有的。
3. **免费开源**：无账号、无订阅、无广告。
4. **可恢复的删除**：回收站、快照、审计日志，降低 Agent 误操作风险。

### 4.3 不构成差异化的点

- 图表数量与视觉精细度：Web 版已具备，竞品也在追赶。
- 自动记账：本期不做，也不打算做。
- 多平台账单接入：本期只支持支付宝与微信。

## 5. 商业模式

### 5.1 变现方式

**主要目标：免费开源引流，积累用户与技术影响力。**

- 短期：完全免费，作为个人作品集/技术展示。
- 中期：积累用户，建立「小遥」品牌认知。
- 长期可能的延伸：
  - 付费高级功能（如 AI 理财顾问，需重新评估隐私承诺）。
  - 企业版（团队财务分析，需多用户模型）。
  - 定制开发与咨询。

### 5.2 成本结构

| 项 | 成本 |
|---|---|
| 开发 | 个人时间，14–24 人日（详见 [04-开发任务清单.md](./04-开发任务清单.md)） |
| 服务器 | **0**，完全本地运行 |
| 域名/托管 | 仅项目主页与下载页，可用 GitHub 免费额度 |
| 代码签名 | 首期不做；后续 Apple Developer / Windows 签名按年付费 |
| 分发 | GitHub Releases 免费 |

### 5.3 延伸与前提

- 任何联网能力（自动更新、云同步、云端 AI）都必须先调整隐私承诺，不能悄悄加入。
- 若做付费功能，必须保持「本地优先」；云端功能需明确标注并默认关闭。

## 6. 风险

### 6.1 市场与采用

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| 桌面安装门槛高于网页 | 转化率低 | 中 | 提供 Windows 一键安装包；macOS 说明右键打开；README 给清晰步骤 |
| 用户已有记账工具 | 转换成本高 | 中 | 用「离线 + Agent」差异化切入；演示模式降低尝试门槛 |
| 账单分析属于低频需求 | 留存低 | 中 | MCP 让 Agent 成为高频入口；后续考虑预算/提醒（需评估范围） |

### 6.2 隐私叙事

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| 托盘常驻与「用完即走」叙事冲突 | 用户信任下降 | 中 | MCP 默认关闭；首次关闭窗口提示；设置可改为「关闭即退出」 |
| MCP 让本机程序读取账单 | 数据可能被 Agent 带出本机 | 中 | 默认关闭、Bearer Token、仅回环、写操作审计、隐私文案明确说明 |
| macOS 未签名被 Gatekeeper 拦截 | 安装失败 | 高 | 文档说明右键打开/系统设置放行；后续补签名与公证 |

### 6.3 技术风险

技术风险 T1–T14 的完整清单与验证方式见 [03-技术方案文档.md](./03-技术方案文档.md) 第 16 节。对 MRD 影响最大的三项：

1. pandas 语义复刻偏差，导致数字与 Web 版不一致（靠 golden 对账，1e-6 容差）。
2. 27 个接口响应形状不统一，前端解析失败（逐个复刻，不抽统一信封）。
3. macOS 无本机构建机、未签名（GitHub Actions 出包，文档说明）。

### 6.4 未签名与信任

- 首期不做代码签名与公证，Windows SmartScreen 与 macOS Gatekeeper 都可能提示。
- 这是有意的取舍：签名成本与发布基础设施未就绪，先验证需求。
- 文档必须如实说明，不能用「已签名」误导用户。

## 7. 成功指标

### 7.1 北极星指标

**完成一次「导入账单 → 打开分析页面」的用户数。**

它同时验证：安装成功、文件格式可解析、前端与 Rust 后端打通、用户愿意导入真实数据。

### 7.2 首发 30 天指标

| 指标 | 目标 | 数据来源 |
|---|---|---|
| GitHub Release 下载量 | 300+ | GitHub Releases 统计 |
| 安装成功率（下载 → 首次启动） | ≥70% | 用户主动反馈 / Issue |
| 首次导入成功率 | ≥90% | 用户反馈 / Issue 样本 |
| 演示模式 → 导入转化率 | ≥30% | 用户反馈 / 访谈 |
| MCP 开启率 | ≥10% | 用户反馈 / 访谈 |
| 7 日留存（再次打开） | ≥20% | 用户反馈 / 访谈 |
| GitHub Star | 100+ | GitHub |
| 有效反馈 | ≥10 条 | Issue / 社群 |

### 7.3 质量指标

| 指标 | 目标 |
|---|---|
| 27 个接口 golden 对账 | 100% |
| 前端改动文件数 | ≤7 |
| 崩溃/无法启动的 Issue 占比 | <5% |
| 安装包体积 | Windows ≤20MB；macOS ≤25MB |
| 断网启动外部请求 | 0 |

### 7.4 不埋点与数据来源

本应用**没有遥测、没有崩溃上报、没有用户行为埋点**。所有指标只能通过以下方式获得：

- GitHub Releases 下载计数。
- GitHub Issues 与 Discussions。
- 用户交流群与主动反馈。
- 作者主动访谈（需用户同意）。

这意味着指标精度有限，但这是隐私承诺的一部分。不得为了指标而加入联网上报。

## 附录 B：决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 是否需要桌面版 | 是 | Web 版存在沙箱、启动门槛、无法常驻三个结构性限制 |
| 技术路线 | Tauri v2 + Rust 重写 + Vue 复用 | 体积小、隐私叙事强、前端复用率高 |
| 是否保留 Python | 否 | 安装包、启动、崩溃面、隐私解释成本都更高 |
| 是否做 MCP | 是 | Agent 是新的查询入口，且可复用同一套服务层 |
| 是否修复 Web 版缺陷 | 否（本期） | 保证统计口径一致；修复需独立版本 |
| 是否做自动更新/遥测 | 否 | 与完全离线的隐私承诺冲突 |
