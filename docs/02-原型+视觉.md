## 0. 文档定位与对齐说明

### 0.1 定位

本文是桌面版的 **UI & UX 标准**，用于：

- 约束前端适配（只允许改 8 个文件）时的视觉与交互边界。
- 统一桌面新增区域（设置页「桌面」分组、托盘、首次关闭提示）的规格与文案。
- 作为 P3 前端验收与视觉验收的依据。

**核心前提：桌面版不重新设计 UI。** 9 个 Web 基线页面的布局、配色、间距、动效沿用 Web 版；桌面端新增 1 个「AI Agent 接入」页与设置页「桌面」分组。

### 0.3 强制规则

1. **不新增设计语言**：不新增颜色、字号、圆角、阴影、动效。
2. **不修改 `main.css`**：新增样式只写在 `Settings.vue` 的 `<style scoped>` 内。
3. **不新增前端依赖**：除 `@tauri-apps/api`、dialog、opener 外不引入 UI 库。
4. **只改 8 个文件**：清单见第 10.1 节。
5. **所有资源本地化**：字体图标、图片、Logo 不引用 CDN。
6. **不做深色模式、不做复杂自绘、不做新动画**；Windows 标题栏只做「隐藏原生 + 34px 极简自绘」。

## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **零重设计** | 不新增设计语言，不调整现有页面布局 |
| **复用设计变量** | 颜色、阴影、圆角全部使用 `main.css:1-68` 的 CSS 变量 |
| **追加而非重排** | 设置页新增「桌面」分组追加在「数据管理」之后，原有区块位置不变 |
| **系统原生** | 文件对话框、托盘菜单、macOS 红绿灯使用操作系统原生外观；Windows 标题栏为 34px 极简自绘 |
| **离线** | 所有图标、字体、图片本地化，不引用任何 CDN |
| **平台一致** | Windows 与 macOS 使用同一套页面，仅窗口装饰与菜单栏不同 |
| **状态完整** | 每个可交互区域都有默认、悬停、焦点、禁用、加载、空、错误状态 |

## 3. 布局与窗口

### 3.1 应用骨架

沿用 Web 版 `AppLayout.vue`：

```
┌──────────────┬──────────────────────────────────────────────┐
│ 侧边栏 240px │ 主内容区（可滚动）                            │
│              │                                              │
│ 首页          │  页面标题 / 筛选 / 统计卡 / 图表 / 列表        │

│ 月度分析      │                                              │
│ 分类分析      │                                              │
│ 时间分析      │                                              │
│ 消费洞察      │                                              │
│ 交易记录      │                                              │
│ 设置          │                                              │
│ 关于作者      │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 侧边栏固定，不随主内容滚动。
- 演示模式横幅位于主内容区顶部，沿用现有样式。
- 浮动筛选（全部/大额/小额）位于右下角，沿用现有样式。

### 3.2 窗口

| 项 | 值 |
|---|---|
| 默认尺寸 | 1280×840 |
| 最小尺寸 | 1024×700（避免触发 768px 移动端断点） |
| 初始显示 | `visible:false`，首帧后 `show()`，避免白屏 |
| 标题栏 | 隐藏系统标题；Windows 自绘 34px，macOS Overlay 保留红绿灯 |
| 自绘范围 | **仅** 标题栏底色/拖拽区/窗口按钮，不做其他自绘 |
| 窗口图标 | 应用 Logo |
| 状态记忆 | 记住尺寸、位置、最大化；屏幕变化时回到主屏可见区 |

### 3.3 平台差异

| 项 | Windows | macOS |
|---|---|---|
| WebView | WebView2 | WKWebView |

| 托盘 | 任务栏通知区域 | 菜单栏图标 |
| 快捷键 | 无新增 | Cmd+Q 退出，Cmd+W 关闭窗口 |

## 4. 核心组件规范

### 4.1 卡片

| 类型 | 规格 |
|---|---|
| 统计卡 | 沿用各页面现有卡片视觉；不引用死代码 `StatCard.vue`，本期不重构 |
| 上传卡 | 沿用现有 `provider-column`：白底、12px 圆角、1px 浅边框、虚线拖拽区 |
| 桌面分组卡 | `div.desktop-section`：白底、`--radius-md`、1px `rgba(0,0,0,.04)`、`--shadow-card`、padding 24px |

### 4.2 按钮

| 类型 | 规格 |
|---|---|
| 主按钮 | 沿用现有主按钮样式，`--primary-color` 背景 |
| 次按钮 `secondary-btn` | 白底、1px `--border-color`、`--radius-sm`、hover 变 `--hover-bg` |
| 危险按钮 `danger-btn` | 文字 `--danger-color`、边框同色 30% 透明 |
| 禁用态 | 沿用现有 `disabled` 样式；不新增透明度规则 |
| 图标按钮 | 沿用现有按钮，不新增圆形图标按钮规范 |

### 4.3 选择器与筛选

- 年度/月度选择器、分类 chip、金额/收支援筛选沿用现有组件。
- 不新增下拉样式；不引入第三方选择器。
- 筛选变化时沿用现有加载态与图表更新方式。

### 4.4 开关

| 项 | 规格 |
|---|---|
| 尺寸 | 44×24 |
| 开启 | `--primary-color` |
| 关闭 | `--border-color` |
| 状态 | 开关旁显示状态点或文字，不单独造新控件 |

### 4.5 状态点与徽标

| 状态 | 颜色 | 用法 |
|---|---|---|
| 运行中 | `--success-color` | MCP 服务 |
| 已停止 | `--secondary-text` | MCP 服务 |
| 异常 | `--danger-color` | 端口占用、启动失败 |
| 演示模式 | 沿用现有黄色横幅 | 全局 |

- 状态点为 8px 圆点。
- 不只靠颜色传达状态：旁边必须有文字（运行中/已停止/异常）。

### 4.6 Toast、Loading 与 Modal

| 组件 | 规则 |
|---|---|
| Toast | 沿用现有 Toast；成功/失败/普通三种，不新增样式 |
| 全局 Loading | 沿用 `uiStore.setGlobalLoading`；不新增进度条 |
| Modal | 新增桌面分组一律使用现有 `Modal.vue`；不使用 `confirm()` |
| 原有 `confirm()` | 上传/删除的原有确认不在本次改动范围（遵守 7 文件边界） |

### 4.7 空状态

| 区域 | 文案 |
|---|---|
| 回收站 | `回收站为空` |
| 快照 | `暂无快照` |
| 审计日志 | `暂无记录` |
| MCP 关闭 | `MCP 服务未开启` |
| 无账单 | 沿用现有首页引导（导入/演示） |
| 无交易 | 沿用现有列表空状态 |

### 4.8 路径框、Token 与代码块

| 元素 | 规格 |
|---|---|
| 路径框 `div.path-box` | 等宽字体 `--font-family-mono`、12px、浅灰底 `#FBFBFD`、`--radius-sm`、可横向滚动 |
| Token `code.token` | 脱敏为 12 个 `•`；复制后 Toast「已复制」 |
| 配置代码块 | 等宽字体、12px、浅灰底、可横向滚动；不新增语法高亮 |

### 4.9 图表容器

- 沿用现有 ECharts 容器尺寸与响应式逻辑。
- 不新增图表配色；不新增动画。
- 图表加载失败时使用 Toast，不新增错误占位图。

## 7. 文件导入交互规范

### 7.1 入口

| 入口 | 行为 |
|---|---|
| 设置页支付宝上传区 | 点击 → 原生文件对话框，过滤 `.csv` |
| 设置页微信上传区 | 点击 → 原生文件对话框，过滤 `.xlsx` / `.csv` |
| 全窗口拖拽 | 文件进入窗口 → 按扩展名分配到对应区 |

### 7.2 原生对话框

```js
const paths = await open({
  multiple: true,
  filters: [
    { name: '支付宝账单', extensions: ['csv'] },
    { name: '微信账单', extensions: ['csv', 'xlsx'] }
  ]
})
```

- 支持多选。
- 不在前端读取文件内容；只传路径。
- 16MB 校验在 Rust；前端展示 Rust 返回的中文错误。

### 7.3 拖拽归属

- `.csv` → 优先支付宝区。
- `.xlsx` → 微信区。
- 同时拖入两种格式时，分别落入对应区。
- 文件进入窗口时，对应卡片显示 `.dragover` 高亮；离开或放下后恢复。
- 拖拽是窗口级事件，两个卡片都可能接收；以扩展名为准。

### 7.4 多文件与结果

- 一次可选择/拖入多个文件，逐个导入。
- 单个文件失败不阻断其他文件。
- 导入结束后用 Toast 汇总：成功 N 个、失败 M 个；失败逐条显示文件名与原因。
- 导入过程中使用全局 Loading，不新增进度条。

### 7.5 校验与错误

| 场景 | 文案 |
|---|---|
| 超过 16MB | `文件 {name} 超过大小限制（16MB）` |
| 支付宝扩展名不符 | `请上传 .csv 格式的文件` |
| 微信扩展名不符 | `请上传 .xlsx,.csv 格式的文件` |
| 演示模式 | `演示模式下无法上传文件，请先退出演示模式` |
| 导入失败 | `导入失败：{原因}` |
| 无文件 | 保持现有空列表 |

### 7.6 重复文件与中文文件名

- 同名不同内容：按 Web 版规则追加 `_1`、`_2`；允许重复计入（D4）。
- 中文文件名：会被清洗成 `csv`/`xlsx`（D3），导致不可见；上传区提示「建议使用英文/数字文件名」。
- 不新增去重逻辑，不修复 D3/D4。

## 9. 交互状态与可访问性

### 9.1 状态定义

| 状态 | 要求 |
|---|---|
| 默认 | 沿用现有样式 |
| 悬停 | 沿用现有 hover；不新增动效 |
| 按下 | 沿用现有 active；不新增缩放/位移动画 |
| 焦点 | 键盘可达；焦点可见沿用现有样式/浏览器默认 |
| 禁用 | 使用 `disabled` 属性；不只用颜色表达 |
| 加载 | 使用全局 Loading；按钮加载时禁用重复点击 |
| 空 | 使用 4.7 与 6.4 的文案 |
| 错误 | 使用 Toast 或空态；不新增错误页 |

### 9.2 键盘与焦点

- 所有可点击元素可用 Tab 聚焦，Enter/Space 触发。
- Modal 打开后焦点进入 Modal；Esc 关闭（沿用现有 Modal 行为）。
- 设置页新增开关、按钮使用原生 `<button>`，不使用 `div` 模拟。
- 不做自定义快捷键（macOS 的 Cmd+Q/Cmd+W 由系统提供）。

### 9.3 对比度与语义化

- 颜色沿用现有变量；不新增低对比度文字。
- 状态不能只靠颜色：运行中/已停止/异常必须有文字。
- 表单控件保留 `<label>` 或 `aria-label`。
- 图片有 `alt`；图标按钮有 `aria-label`。

### 9.4 已知可访问性缺口（不阻塞本期）

- 未做完整的屏幕阅读器回归。
- 未自定义焦点环。
- 未做高对比度模式。
- 未做 reduced-motion 专项适配（现有动效较少）。

> 本期沿用 Web 版现状，不新增可访问性功能；上述缺口记录在案，后续版本处理。
