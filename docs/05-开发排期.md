## 1. 排期口径

### 1.1 基本假设

| 项 | 假设 |
|---|---|
| 人员 | 1 名全栈开发，全程投入 |
| 工时 | 每个工作日按 1 人日计 |
| 起始日 | **D1 = 实际启动日**（本文不写死日历日期） |
| 工作日 | 仅计工作日，不含周末与法定假日 |
| 范围 | P0–P6，共 61 个任务（见 [04-开发任务清单.md](./04-开发任务清单.md)） |
| 代码基线 | 前端为 Web 版冻结基线（只允许改 7 个文件）；后端 Rust 全量重写 |
| 环境 | Windows 11 本机开发；macOS 通过 GitHub Actions 构建 |

### 1.2 人日与日历日

| 口径 | 数值 | 出处 | 用途 |
|---|---|---|---|
| 人日 | 14–24 人日 | 04 §10.1 | 任务工作量，逐项相加 |
| 日历日 | **14–22 个工作日** | 本文 §1.3 | 单人实际排期 |
| MVP | 8–12 人日 | 04 §10.4 | 导入 → 18 接口 → 9 页面 |

差异来源：部分任务可并行（P1 三个解析器、P2 五组分析、P3 静态适配、P4 只读工具），另留约 2 天缓冲应对 rmcp/Tauri 小版本 API 漂移与 macOS 首次 CI 调试。

### 1.3 D1–D22 相对日

- **基准排期 19 个工作日**（D1–D19）；D20–D22 为缓冲与验收，按实际情况使用。
- 所有周计划按「第 N 周」表述，D1 落在第 1 周周一。
- 若实际启动日确定，可用第 12 节日历模板换算为具体日期。

## 7. 风险预警

| 检查点 | 风险 | 触发信号 | 应对 |
|---|---|---|---|
| **D1–D2** | Tauri/rmcp API 漂移 | 编译 spike 失败 | 锁定更早 3.x；查 capabilities；记录替代写法 |
| **D5** | 解析器语义偏差 | 真实样例解析失败 | 用 fixture 定位编码/表头/日期；优先修解析器 |
| **D8** | pandas 对账超期 | 仍有 >5 个接口不绿 | D10 先冻结 18 个在用接口，P2b 延后到 0.2.0 |
| **D10** | 性能不达标 | 1 万条 `/analysis` > 200ms | 按 `(generation, params)` 缓存；预计算年度聚合 |
| **D12** | 27 接口对账未完成 | golden 非 100% | 不发布；保留 0.1.0 开发版；逐字段定位 |
| **D13** | MCP 鉴权/端口问题 | 401/403 用例失败 | 检查 Token、Origin、监听地址；端口占用明确报错 |
| **D16** | macOS CI 不可用 | runner 拉取失败/超时 | 先发 Windows；macOS 顺延并标注「构建中」 |
| **D19** | 安装验收失败 | 干净环境无法启动 | 检查 WebView2、数据目录权限、安装器配置 |
