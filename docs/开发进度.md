### 5.8 `/analysis` 单元 3 交付记录（P2-8）

新增 `crates/bill-services/src/charts.rs`，10 个图表数据函数。这些函数最容易出错的地方不是算法，而是**顺序**：

| 函数 | 顺序 / 边界要点 |
|---|---|
| `analyze_sankey` | 节点按 `unique()` 首次出现顺序编号；连线按 `groupby(分类, 来源)` 排序 |
| `generate_chord_data` | 7 个星期节点固定输出；连线按星期名 Unicode 排序（周一→周三→周二→周五→周六→周四→周日） |
| `generate_funnel_data` | `pd.cut(observed=False)` 保留 6 个空桶；按金额降序，并列保持桶顺序 |
| `generate_quadrant_data` | 过滤 `total >= 50 && count >= 2`；分类取 `mode()` 首个（并列取字典序最小） |
| `generate_radar_data` | 分类取前 8；季度只取序号 1–4（**不区分年份**）；`max = 最大值 × 1.1` |
| `generate_wordcloud_data` | 仅保留金额 `> 10`；降序稳定排序后取前 100 |
| `generate_themeriver_data` | 月 × 前 10 分类全量展开，缺失月份/分类补 `0.0` |
| `generate_boxplot_data` | 散点保持数据集行顺序；`box_data` 用 `np.percentile` 线性插值（不四舍五入） |
| `generate_heatmap_data` | 输出 `[小时, 星期(周一=0), 笔数]`，按星期、小时排序 |
| `generate_pareto_data` | 分类降序 + `cumsum / total × 100` 保留 2 位，取前 15 |

- 期望值来自 Web 版 `analyze_sankey` + `services/generators.py` 在同一份 24 行数据上的实际输出，包含 `880.0000000000001` 这类浮点尾数。
- `cargo test -p bill-services --test charts` → 11 passed。
- `cargo test --workspace` → 150 passed；clippy 与 fmt 无差异。
- 无 UI，跳过 Playwright（`/analysis` 仍未接路由）。

### 5.9 `/analysis` 单元 4 交付记录（P2-8 完成）

`insights.rs` 补齐 `generate_smart_tags` 与 `generate_story_data`，并在 `bill-api` 接通 `/analysis`：

| 函数 | 复刻要点 |
|---|---|
